# Protein and Genome Foundation Models for a Solo-Developer Interactive Web App (state as of 2026-11-25)

Scope note for the report writer: every section below is written from the point of view of a
$0–20/month, no-institutional-affiliation, one-developer open-source web app. The single most
important finding of this research is in the "Protein language models and embeddings" and
"Mechanistic interpretability" sections: **the ESM family was relicensed to MIT in 2026 under
Chan Zuckerberg Biohub, and official sparse autoencoders with agent-generated feature labels
shipped with it.** That changes what is buildable at $0 more than anything else in this landscape.

---

## Structure prediction: AlphaFold 3, Boltz, Chai, Protenix, OpenFold3, ESMFold, SimpleFold, and 2026 arrivals

### Takeaway
AlphaFold 3 remains the licensing dead end (non-commercial, gated, no redistribution), but by late
2026 there are at least four genuinely Apache-2.0/MIT open-weights models at or near AF3 parity —
Boltz-2, Protenix-v1, OpenFold3 and the new ESMFold2 — so a hobby project never needs to touch AF3
terms. For a web app the decisive insight is that **folding is the wrong thing to spend money on**:
AlphaFold DB already contains the whole human proteome for free, and the interesting 2026 models are
better used for interpretability and design than for re-folding what is already downloadable.

### Cited Findings
- **AlphaFold 3 weights are non-commercial, gated, and non-redistributable.** The weights terms (latest version confirmed dated 2024-11-09) state the parameters are free of charge "only for certain non-commercial uses," forbid use "in connection with commercial activities, including research on behalf of commercial organizations," and prohibit redistribution except within one's own organization. Access is granted at Google's discretion, and the parameters "may only be used if received directly from Google" — one university notes each user must request their own personal copy — [AlphaFold3 WEIGHTS_TERMS_OF_USE (mirror)](https://code.rc.uab.edu/rc-data-science/community-containers/Alphafold3/-/blob/6166cdc03cb35acb23815aab7aeb749c213c6d8a/WEIGHTS_TERMS_OF_USE.md); [BU Research Computing AlphaFold3 notes](https://www.bu.edu/tech/support/research/software-and-programming/common-languages/python/python-ml/alphafold3)
- **AlphaFold 3 source code is CC-BY-NC-SA 4.0** — i.e. the code is also non-commercial and share-alike, separately from the weights — [AlphaFold3 weights terms mirror](https://code.rc.uab.edu/rc-data-science/community-containers/Alphafold3/-/blob/6166cdc03cb35acb23815aab7aeb749c213c6d8a/WEIGHTS_TERMS_OF_USE.md)
- **I found no 2026 revision of the AlphaFold 3 weights terms.** A 2026-dated DeepMind terms document that surfaces in search covers *AlphaProtein Novo*, a different product, whose AlphaFold 3 component is "governed by its own respective terms" — [AlphaProtein Novo weights terms](https://raw.githubusercontent.com/google-deepmind/alphaprotein-novo/main/WEIGHTS_TERMS_OF_USE.md)
- **Boltz-2 is MIT — weights, inference code and (promised) training code.** MIT's Jameel Clinic released it under a permissive license explicitly allowing commercial developers to use the model internally with proprietary data; the repo README states "our model and code are released under MIT License, and can be freely used for both academic and commercial purposes" — [MIT CSAIL announcement](https://www.csail.mit.edu/news/mit-releases-breakthrough-protein-binding-affinity-model-expanding-role-ai-drug-discovery); [Boltz README](https://raw.githubusercontent.com/jwohlwend/boltz/HEAD/README.md); [MIT Jameel Clinic Boltz-2](https://jclinic.mit.edu/boltz-2)
- **Boltz-2's distinguishing capability is binding-affinity prediction**, not just structure — it is framed as a "protein-binding affinity model" — [MIT CSAIL](https://www.csail.mit.edu/news/mit-releases-breakthrough-protein-binding-affinity-model-expanding-role-ai-drug-discovery)
- **Caveat on Boltz-2 training code:** the README still notes updated Boltz-2 training code is "coming soon," so the training pipeline may not have shipped — [Boltz README](https://raw.githubusercontent.com/jwohlwend/boltz/HEAD/README.md)
- **NVIDIA's hosted Boltz-2 is governed by a different licence.** NVIDIA's model card says "use of this model is governed by the NVIDIA Community Model License," listing MIT only as additional information — a licence divergence that recurs across every NVIDIA-hosted model below — [NVIDIA Boltz-2 model card](https://build.nvidia.com/mit/boltz2/modelcard)
- **Protenix-v1 (ByteDance) is Apache 2.0 for both code and weights**, and is presented as the first fully open-source biomolecular structure predictor reaching AlphaFold3-level performance under matched conditions; a variant `Protenix-v1-20250630` trained on more recent data also exists — [Protenix PyPI 1.0.8](https://pypi.org/project/protenix/1.0.8/); [Protenix README](https://raw.githubusercontent.com/bytedance/Protenix/main/README.md); [MarkTechPost, 2026-02-08](https://www.marktechpost.com/2026/02/08/bytedance-releases-protenix-v1-a-new-open-source-model-achieving-af3-level-performance-in-biomolecular-structure-prediction/)
- **NEW/CHANGED 2026 — Protenix-v2 weights are proprietary.** A mirror states Protenix-v2 "model weights are proprietary and not released under any open-source license," so the open-weights status applies to v1 only — [Protenix Gitee mirror](https://gitee.com/ByteDance/Protenix)
- **Chai-1 is Apache 2.0 for code and weights** per the official repo, though an earlier review quotes the authors describing a non-commercial package — the licence appears to have been loosened, and the change date is unconfirmed — [chai-lab repo](https://github.com/aiproteins/chai-lab); [PREreview record](https://prereview.org/reviews/14450747)
- **OpenFold3 is Apache 2.0 across software components**, and the Hugging Face card for OpenFold3-preview states the model is "released under Apache 2.0 license," with gated-but-automatic access ("you will automatically get access to the model after answering the following simple questions") — [OpenFold3 HF README](https://huggingface.co/OpenFold/OpenFold3/blob/refs%2Fpr%2F12/README.md); [OpenFold3 docs](https://openfold-3.readthedocs.io/); [OpenFold3 HF model tree](https://huggingface.co/OpenFold/OpenFold3/tree/main)
- **NEW 2026 — OpenFold3 shipped a major update plus public training data.** A March 2026 announcement covers "a major OpenFold3 update and public release of training data for reproducibility" and full-stack tooling; the GitHub README's "still in development" language may predate it — [OpenFold3 update coverage](https://www.pulse.bot/ai/news/openfold-consortium-announces-major-openfold3-update-and-public-release-of-training-data-for-reprodu-0ca506ae-c00b-427f-a87c-c9c28868b1ba/); [Businesswire 2026-03-13](https://www.businesswire.com/news/home/20260313170622/en)
- **NVIDIA's hosted OpenFold3 again diverges:** "use of this model is governed by the NVIDIA Open Model License. ADDITIONAL INFORMATION: Apache 2.0 License" — [NVIDIA OpenFold3 model overview](https://docs.api.nvidia.com/nim/re/reference/openfold-openfold3)
- **NEW 2026 — ESMFold2 (Biohub, released 2026-05-27) is MIT-licensed, MSA-free, and claims to beat AlphaFold 3 on interaction benchmarks.** It combines ESMC 6B language-model embeddings with a diffusion-based structure architecture and a "looped transformer" that scales compute at inference. Claims: it "leads standard folding benchmarks for protein-protein and antibody-antigen interactions"; from ESMC representations alone it "predicts antibody-antigen binding poses more successfully than AlphaFold 3"; given the same MSA input as AlphaFold it is "the strongest predictor on both benchmarks"; accuracy improves with more compute when multiple predictions are confidence-ranked — [Biohub: world model of protein biology](https://biohub.org/news/world-model-of-protein-biology/); [Rosetta Commons coverage 2026-06-09](https://rosettacommons.org/2026/06/09/biohub-releases-open-source-models-that-utilize-evolution-to-design-disease-target-binders/); [biohub/esm README](https://raw.githubusercontent.com/biohub/esm/main/README.md)
- **ESMFold2 reportedly "compared favorably" against Chai-1, Boltz-1 and AlphaFold 3 — but no numbers are published on the announcement pages** — [Rosetta Commons](https://rosettacommons.org/2026/06/09/biohub-releases-open-source-models-that-utilize-evolution-to-design-disease-target-binders/)
- **ESMFold2 hosted API model id is `esmfold2-fast-2026-05`**; the Sync API folds inputs up to **768 tokens**, the Batch API up to **4096 tokens**, queued tasks expire after 24 h and results are kept 31 days — [biohub/esm README](https://raw.githubusercontent.com/biohub/esm/main/README.md)
- **SimpleFold (Apple) — flow-matching folding with no MSA, no pair representation, no triangle modules.** Largest model is **3B params**, trained on >8.6M distilled structures plus PDB. SimpleFold-3B is "competitive … compared to state-of-the-art baselines"; on CAMEO22 it is "comparable to the best folding models (e.g., ESMFold, RoseTTAFold2, and AlphaFold2)". Critically for this project: **SimpleFold-100M recovers ~90% of the best model's performance while being "very efficient in inference even on consumer-level devices,"** and the code ships both PyTorch and **MLX** backends (recommended on Apple hardware). ICLR 2026 paper; code at apple/ml-simplefold — [arXiv 2509.18480v4](https://arxiv.org/pdf/2509.18480v4); [Apple ML Research](https://machinelearning.apple.com/research/simplefold); [apple/ml-simplefold](https://github.com/apple/ml-simplefold)
- **CASP16 context (assessment papers published 2025):** 110 groups, 22 countries, 200 methods. "In most areas, deep learning methods dominate, particularly AlphaFold variants." **AlphaFold3 yields only "a modest improvement over AlphaFold2."** Monomer prediction is "a largely solved problem." Complexes "remain an unsolved challenge," with calls for better ranking and stoichiometry prediction. Ligands: DL substantially beats traditional methods but "often fall short of experimental accuracy." **RNA: DL methods are "notably unsuccessful at present and are not superior to traditional approaches"** — [Kryshtafovych et al., CASP XVI progress and bottlenecks](https://pubmed.ncbi.nlm.nih.gov/41178755/); [CASP16 monomer assessment (Yuan et al.)](https://moodle2.units.it/pluginfile.php/811538/mod_resource/content/2/Proteins%20-%202025%20-%20Yuan%20-%20CASP16%20Protein%20Monomer%20Structure%20Prediction%20Assessment.pdf)
- **Free hosted inference — ESMFold is a "Free Endpoint" on build.nvidia.com**; Boltz-2 there is a downloadable NIM ("ready for commercial use") rather than a free hosted endpoint — [NVIDIA ESMFold model card](https://build.nvidia.com/meta/esmfold/modelcard); [NVIDIA ESMFold API reference](https://build.nvidia.com/meta/esmfold/apireference); [NVIDIA Boltz-2 model card](https://build.nvidia.com/mit/boltz2/modelcard)
- **The old ESM Atlas fold endpoint (`api.esmatlas.com/foldSequence/v1/pdb/`, POST raw sequence, no token) is widely documented in third-party code but its live status is unconfirmed.** The authoritative repo now says "our API migrated from forge.evolutionaryscale.ai to biohub.ai" and directs users to create API tokens in the biohub.ai developer console — strongly implying the unauthenticated endpoint is superseded — [community fold script](https://huggingface.co/spaces/42Cummer/BroteinShake/blob/main/scripts/foldprotein.py); [biohub/esm README](https://raw.githubusercontent.com/biohub/esm/main/README.md)
- **ColabFold's public MMseqs2 MSA server has no published rate limit, and pipeline docs steer bulk users away from it:** "If you aim to carry out a large number of predictions, please use the local mmseqs search module or setup and use your own custom MMSeqs2 API," with `--msa_server_url` available to point at a private endpoint — [nf-core/proteinfold ColabFold docs](https://nf-co.re/proteinfold/dev/docs/usage/colabfold); [ColabFold repo](https://github.com/sokrypton/ColabFold)
- **Free Colab GPU caps sequence length, not the MSA server:** on a ~16 GB T4 the max length is ~2000 residues — [ColabFold repo](https://github.com/sokrypton/ColabFold)
- Third-party hosted runners exist for essentially all of these (Tamarind for OpenFold3, ESM-C, RFdiffusion3; Neurosnap for BoltzGen; Rowan for BoltzGen), i.e. commercial web servers rather than free tiers — [Tamarind OpenFold3](https://www.tamarind.bio/tools/openfold); [Tamarind pricing](https://tamarind.bio/pricing); [Neurosnap BoltzGen post](https://neurosnap.ai/blog/post/boltzgen-a-universal-generative-framework-for-biomolecular-binder-design/6914d2838b9522d6ffefa787); [Rowan BoltzGen](https://rowansci.substack.com/p/breaking-boltzgen-now-live-on-rowan)

### Inferences
- **AlphaFold 3 is simply out of scope for this project** and should be dropped from the 2.0 plan entirely: non-commercial weights that cannot be redistributed, plus CC-BY-NC-SA code, are incompatible with an open-source portfolio app, and nothing is lost because Boltz-2/Protenix-v1/OpenFold3/ESMFold2 are permissively licensed and at or above AF3 parity on the dimensions that matter here.
- **The licence pattern to internalise: upstream permissive, NVIDIA-hosted restrictive.** Boltz-2, OpenFold3, ProteinMPNN, RFdiffusion and Evo 2 all show "NVIDIA Community/Open Model License" on build.nvidia.com with the real licence demoted to "additional information." If the app calls an NVIDIA-hosted endpoint, it inherits NVIDIA's terms, not MIT/Apache. Using NVIDIA's *free* ESMFold endpoint is fine for a demo but should not be described in the repo as "MIT ESMFold."
- **SimpleFold-100M is the only credible candidate for on-device/edge folding** in this landscape — explicitly designed for consumer devices with an MLX backend. That makes a "fold a sequence you typed, locally, no server" feature realistic on the developer's own Mac, though not in-browser (see browser section).
- **Live folding should be a cherry on top, not a data pipeline.** Since CASP16 declares monomers "largely solved" and AFDB already holds every human monomer, the differentiating 2.0 feature is not folding 20k proteins — it is *interpreting* structures that are already free. Reserve a folding call for user-supplied sequences and mutants.
- **CASP16's RNA and complex failures are a useful honesty feature**: an app that shows confidence and says "complexes remain unsolved; this is a prediction, not a structure" is more credible than one that renders everything identically. pLDDT colouring already does half of this.

### Gaps
- **No head-to-head CASP16 numbers for Boltz-1/2, Chai-1 or Protenix.** The CASP16 assessment papers discuss AlphaFold variants; the searches did not return a table placing the open models against AF3 on CASP16 targets. The PXMeter paper is cited as evaluating Protenix, AlphaFold3, Boltz-1 and Chai-1 on matched tasks but I did not retrieve its numbers — [PXMeter referenced via Protenix README](https://raw.githubusercontent.com/bytedance/Protenix/main/README.md)
- **ESMFold2's "beats AlphaFold 3" claim is unquantified** on all pages I could read. It is a company/institute claim referencing a preprint I did not fetch. Treat as unverified until the preprint numbers are checked.
- **Whether `api.esmatlas.com` still answers is untested.** I found no deprecation notice and no changelog. This needs a live curl, not a search.
- **No published rate limits** for: the ColabFold MMseqs2 server, the Foldseek public server, the AFDB/EBI API, or build.nvidia.com free-endpoint quotas. Also no confirmation of whether build.nvidia.com grants free credits to new accounts.
- **GPU/VRAM requirements per model** (AF3-class models typically need 24–80 GB for long inputs) were not confirmed from primary sources in this research and should be checked per repo before planning any self-hosted inference.
- **PoseBusters** results for the 2026 cohort of models were not retrieved.

## Protein language models and embeddings, and the smallest model that is good enough

### Takeaway
The headline 2026 change is that **the ESM family was relicensed to MIT under Chan Zuckerberg Biohub**
(copyright "Chan Zuckerberg Biohub, Inc.", 2026) — ESMC 6B, ESMFold2 and the sparse autoencoders all
ship under plain MIT with no field-of-use restriction, superseding the old non-commercial Cambrian
licences that still govern the legacy EvolutionaryScale ESM-3 repos. For this app's similarity map,
the cheapest correct answer is not to run a model at all: **UniProt publishes precomputed ProtT5
per-protein embeddings for the entire human reference proteome as a single HDF5 file.**

### Cited Findings
- **NEW 2026 — the ESM licence is now MIT, held by Chan Zuckerberg Biohub, dated 2026, with no non-commercial or field-of-use restriction.** The LICENSE.md grants rights to "use, copy, modify, merge, publish, distribute, sublicense, and/or sell copies," free of charge to any person, with only the attribution condition — [biohub/esm LICENSE.md](https://raw.githubusercontent.com/biohub/esm/main/LICENSE.md)
- The README confirms the MIT licence covers **ESMC, ESMFold2 and the SAEs**, and describes no non-commercial licence; use is additionally subject to a separate **Acceptable Use Policy** — [biohub/esm README](https://raw.githubusercontent.com/biohub/esm/main/README.md)
- **Organisational change:** EvolutionaryScale's team was recruited into Biohub; the ESM SDK now lives at github.com/biohub/esm and the API "migrated from forge.evolutionaryscale.ai to biohub.ai," with some code classes still referencing "Forge." The 2024 software citation still names EvolutionaryScale, and the README does not explicitly announce a rename — [Rosetta Commons](https://rosettacommons.org/2026/06/09/biohub-releases-open-source-models-that-utilize-evolution-to-design-disease-target-binders/); [biohub/esm README](https://raw.githubusercontent.com/biohub/esm/main/README.md); [apis.io EvolutionaryScale profile](https://apis.io/providers/evolutionaryscale/)
- **ESMC 6B: 6B parameters, 80 layers, Safetensors F32, GPU required.** Flash attention requires bfloat16; `transformer_engine` and `xformers` are optional. The HF page shows no gating notice. **Licence tags on the HF page are ambiguous — both "mit" and "other" are listed, with no licence text on the page** — [biohub/ESMC-6B](https://huggingface.co/biohub/ESMC-6B)
- **ESMC was trained on ~2.8 billion sequences** from across all of life, including extremophiles and over 20,000 human proteins — [Biohub news](https://biohub.org/news/world-model-of-protein-biology/); [Rosetta Commons](https://rosettacommons.org/2026/06/09/biohub-releases-open-source-models-that-utilize-evolution-to-design-disease-target-binders/)
- **Hosted API model ids:** `esmc-600m-2024-12`, `esmc-6b-2024-12`, `esmfold2-fast-2026-05`, via the Biohub Platform at biohub.ai with tokens from the developer console. The platform is described as a "freely accessible platform" with guardrails on controlled pathogens and toxins; elevated access can be requested. **No explicit free-tier quota is defined in the README** — [biohub/esm README](https://raw.githubusercontent.com/biohub/esm/main/README.md)
- **ESMC and ESMFold2 are in Hugging Face Transformers from v5.16.0**, and the `esm` package v3.4.1.post1 on PyPI supports both — so integration is a standard `AutoModel.from_pretrained` path — [biohub/esm README](https://raw.githubusercontent.com/biohub/esm/main/README.md)
- **LEGACY/CONFLICTING — the older EvolutionaryScale licences were non-commercial.** The Cambrian Open License Agreement covers ESM3-open and ESMC 300M; ESMC 600M weights were under the non-commercial Cambrian licence; ESMC 6B was accessible "via EvolutionaryScale Forge for free non-commercial use," with commercial use through Amazon SageMaker under the Cambrian Inference Clickthrough License Agreement — [Cambrian Open License Agreement](https://www.evolutionaryscale.ai/policies/cambrian-open-license-agreement); [Cambrian Inference Clickthrough License](https://evolutionaryscale.ai/policies/cambrian-inference-clickthrough-license-agreement); [esmc-600m-2024-12 model card](https://huggingface.co/EvolutionaryScale/esmc-600m-2024-12)
- **ESM-3 open variant remains non-commercial.** ESM3-open is the 1.4B model, "the smallest and fastest in the family," available only under a non-commercial Community License; downloading requires accepting the licence on HF. The licence limits use to individuals and non-commercial organisations, **bars hosting the model behind an API** and bars drug development; fine-tunes inherit the restriction. Medium/large variants (up to 98B) are commercial-only via API and partners — [esm3-sm-open-v1 model card](https://huggingface.co/EvolutionaryScale/esm3-sm-open-v1); [esm3-sm-open-v1 README](https://huggingface.co/EvolutionaryScale/esm3-sm-open-v1/blob/main/README.md); [VentureBeat](https://venturebeat.com/ai/meta-alum-launches-ai-biology-model-that-simulates-500-million-years-of-evolution)
- **PRECOMPUTED EMBEDDINGS — UniProt publishes ProtT5 embeddings as HDF5.** Generated with the **ProtT5** model. **Per-protein** files (one fixed-length vector per sequence) are available for **UniProtKB/Swiss-Prot** and reference proteomes for **Homo sapiens (UP000005640_9606)**, Arabidopsis, C. elegans, E. coli, mouse, rat and SARS-CoV-2. **Per-residue** files are much larger and hosted separately at `https://ftp.ebi.ac.uk/pub/contrib/UniProt/embeddings/current_release`. Sequences >12k residues are excluded for GPU-memory reasons ("a handful of proteins") — [UniProt embeddings README (DDBJ mirror)](https://ddbj.nig.ac.jp/public/mirror_database/uniprot/knowledgebase/embeddings/README); [Swiss-Prot per-protein directory listing](https://ddbj.nig.ac.jp/public/mirror_database/uniprot/knowledgebase/embeddings/uniprot_sprot/)
- **Embedding dimensions: ProtT5 = 1024.** ESM-2 dims by size: **8M → 320, 35M → 480, 150M → 640** — [PMC11358375](https://pmc.ncbi.nlm.nih.gov/articles/PMC11358375)
- **ESM-2 vs ProtT5 on function prediction — ProtT5 wins in the one direct comparison found.** In a STAR-GO evaluation ProtT5 beat both ESM-1b and ESM-2 on most metrics; Molecular Function Fmax 0.719 (ProtT5) vs 0.675 (both ESM models) — [STAR-GO, arXiv 2512.05245](https://arxiv.org/pdf/2512.05245)
- **Evidence that small PLMs are nearly as good, and that scale is not monotonic.** On functional-peptide prediction: ESM-2 35M → 0.951 accuracy, 150M → 0.958, 15B → 0.964 — tiny gains for a ~400× parameter increase — [pLMFPPred, arXiv 2309.14404](https://arxiv.org/pdf/2309.14404). On salty-peptide prediction the **8M** ESM-2 fusion scored *highest* held-out ROC-AUC (0.700) vs 35M (0.685) and 150M (0.680), and the authors note PLM scale "wasn't consistently linked to better results" — [SaltyMeta, arXiv 2609.16809](https://arxiv.org/pdf/2609.16809)
- **SaProt — structure-aware vocabulary (amino acid + Foldseek 3Di tokens), largest version 650M**, evaluated on 10 downstream tasks and reported to outperform established baselines. Developers recommend structure-aware input for the 35M and 650M models, while the 1.3B handles amino-acid-only input reasonably — [SaProt repo](https://www.github.com/westlake-repl/SaProt); [SaProt_650M_AF2](https://huggingface.co/westlake-repl/SaProt_650M_AF2); [SaProt ICLR 2024 paper](https://proceedings.iclr.cc/paper_files/paper/2024/file/1c42513b8895ab11fbbb5b7e8e6b6b02-Paper-Conference.pdf)
- **ProstT5 — bilingual T5 translating between amino acids and 3Di tokens**, built on ProtT5. On SCOPe40 remote homology, ProstT5-predicted 3Di reached superfamily ROC-AUC **0.45**, close to experimental-structure 3Di at **0.49**, and vastly above sequence-only MMseqs2 at **0.06** — [ProstT5 preprint](https://www.biorxiv.org/content/10.1101/2023.07.23.550085.full.pdf)
- **2026 PLM arrivals (lower confidence, from search listings only):** "ProtSent: Protein Sentence Transformers" — [arXiv 2605.06830](https://huggingface.co/papers/2605.06830.md); "Task- and dataset-specific information in protein language models" — [arXiv 2608.12090](https://arxiv.org/pdf/2608.12090); PoET-2, a retrieval-augmented multimodal protein foundation model covered in Feb 2026 though its arXiv preprint is dated Aug 2025 — [PoET-2 coverage](https://letsdatascience.com/news/poet-2-introduces-retrieval-augmented-multimodal-protein-fou-308fb384); Microsoft's Dayhoff family and Profluent's ProGen3 appear in results but their release dates are not established by the sources I saw.
- **BioReason-Pro (Arc Institute)** is a reasoning model that "integrates protein embeddings from the ESM3 foundation model to generate reasoning traces explaining its predictions" — relevant as a pattern for an explainable LLM guide, though its release date is unconfirmed — [Arc BioReason-Pro](https://arcinstitute.org/news/bioreason-pro)

### Inferences
- **The 2026 MIT relicensing is the single biggest unlock for this project.** Under the old Cambrian terms, an ESM-based public web app was arguably prohibited (ESM3's licence explicitly bars hosting the model behind an API). Under MIT, ESMC + ESMFold2 + the SAEs can be used, hosted, and shipped in an open-source app with attribution only. Every ESM-related design decision in the pre-2026 version of this project should be revisited.
- **Caution on relying on the MIT claim for ESMC-6B specifically:** the HF model card carries both "mit" and "other" tags with no licence text, and an Acceptable Use Policy applies on top. The LICENSE.md in the SDK repo is unambiguous MIT, but a careful project should cite the repo LICENSE.md, link the AUP, and avoid claiming "MIT, no strings."
- **For the similarity map, download, don't compute.** UniProt's human-proteome ProtT5 per-protein HDF5 is a single file covering ~20k proteins with 1024-dim vectors, and ProtT5 is the model that actually won the one direct function-prediction comparison found. That is a zero-GPU, zero-dollar path to a UMAP of the whole human proteome — a strict upgrade over 54 hand-built fixtures, and it removes the GPU question from the critical path entirely.
- **The "smallest good enough" answer for similarity maps is smaller than intuition suggests.** With 35M→150M→15B buying 0.951→0.958→0.964 on one task, and 8M beating both larger models on another, a 35M–150M ESM-2 is defensible for interactive/exploratory embedding work. Reserve 600M–6B for the interpretability features where the SAEs only exist for the 6B model.
- **The 3Di alphabet (ProstT5/SaProt/Foldseek) is an under-exploited UI opportunity.** It turns structure into a 20-letter string, which means structure can be rendered as a *sequence track* in the browser with no 3D cost, aligned next to the amino-acid track and per-residue model features. ProstT5 also means 3Di can be obtained for a sequence with no structure.
- **ProtT5 1024-dim × 20k proteins is a trivially small payload.** 20,000 × 1024 × 4 bytes ≈ 82 MB as float32, ≈ 41 MB as float16, and far less quantised — i.e. the entire human proteome embedding matrix can plausibly be shipped as a static asset and searched client-side, which fits the $0 static-hosting constraint.

### Gaps
- **UniProt's README does not state embedding dimensions or file sizes**, so the exact human per-protein HDF5 size is unknown (the 1024-dim figure comes from a separate source, not UniProt's README). The release version/date is also unstated — the page shows only a 2002–2024 copyright range and a `current_release` path. Needs a HEAD request against the FTP path.
- **No precomputed ESM-2 or ESM C embeddings for the human proteome from an official source were found.** UniProt's offering is ProtT5 only. A third-party set of 128-dim ProteinCLIP embeddings for Swiss-Prot exists on HF but is not UniProt's — [ProteinCLIP dataset](https://zenodo.org/records/11506091)
- **ESMC embedding dimension and on-disk size are not stated** on the HF page (6B params, 80 layers, F32 is all that is given). VRAM needs for 6B inference were not confirmed from primary sources.
- **Biohub Platform free-tier quotas and any per-token pricing are unpublished.** Third-party directories describe a "Free" starting price and "free non-commercial access for academic researchers, subject to application review," plus "pricing negotiated per workload" for commercial Forge use with no public list pricing — all secondary, and the pre-relicensing framing may now be stale — [SourceForge Biohub listing](https://sourceforge.net/software/product/Biohub/); [apis.io EvolutionaryScale plans](https://apis.io/plans/evolutionaryscale/evolutionaryscale-plans-pricing/)
- **Ankh**: I found no primary-source information in this research. Unverified.
- **No clean SaProt-vs-ProstT5 benchmark on the same task** was found; PFMBench evaluates both but per-model scores were not retrieved.
- The small-PLM evidence comes from **peptide-level tasks**, not whole-protein similarity or GO transfer, so it is suggestive rather than decisive for this app's use case.

## Protein language models running in the browser (transformers.js, ONNX Runtime Web, WebGPU)

### Takeaway
ESM-2 has been converted to ONNX for Transformers.js at 150M and 650M, and Transformers.js supports
WebGPU via a one-line `device: 'webgpu'` option — so in-browser PLM inference is technically
available today. But I found **no benchmark of ESM-2 speed in a browser**, and browser WebGPU support
is still uneven, so any claim about in-browser throughput would be speculation.

### Cited Findings
- **ONNX ESM-2 conversions exist for Transformers.js**, including 150M (`Xenova/esm2_t30_150M_UR50D`) and 650M (`Xenova/esm2_t33_650M_UR50D`); the model cards recommend converting with 🤗 Optimum and placing ONNX weights in a subfolder — [Xenova/esm2_t30_150M_UR50D](https://huggingface.co/Xenova/esm2_t30_150M_UR50D/blob/main/README.md); [Xenova/esm2_t33_650M_UR50D](https://huggingface.co/Xenova/esm2_t33_650M_UR50D/blob/main/README.md)
- **WebGPU is a single option flag:** "Enabling WebGPU acceleration is as simple as setting `device: 'webgpu'` when loading a model." The docs show a feature-extraction example using mean pooling with normalisation — exactly the pattern for pooling per-residue embeddings into one sequence vector — [Transformers.js WebGPU guide](https://huggingface.co/docs/transformers.js/guides/webgpu)
- **Package version matters:** use `@huggingface/transformers` v3.x+; `@xenova/transformers` is v2 and does not support WebGPU — [SitePoint WebGPU vs WASM in Transformers.js](https://www.sitepoint.com/webgpu-vs-webasm-transformers-js/)
- **Browser support is the main caveat:** Firefox 118+ supports WebGPU behind a flag, Safari support "remains experimental," and demos may require a feature flag. The fallback is WASM, where "inference runs entirely on the CPU" — [SitePoint](https://www.sitepoint.com/webgpu-vs-webasm-transformers-js/); [Transformers.js WebGPU guide](https://huggingface.co/docs/transformers.js/en/guides/webgpu)

### Inferences
- **The realistic in-browser tier is ESM-2 8M/35M/150M, not 650M.** Given that 320–640 dim small models are competitive on the function-ish tasks cited earlier, and that a 650M ONNX model is a very large download for a web page, an 8M–35M model is the one that could plausibly run interactively client-side. A 150M model is borderline — feasible as an explicit opt-in "load the model" action, not on page load.
- **The genuinely novel, cheap feature this enables is mutation scratchpad, not bulk embedding.** Precompute the 20k-protein embedding matrix server-side (or download UniProt's), ship it static, and use a tiny in-browser PLM only for sequences the user *types or mutates* — which is exactly the case where no precomputed answer can exist. That keeps cost at $0 and makes the interactive part feel instant.
- Because 3Di is just a 20-letter alphabet, a small ONNX ProstT5-style model would in principle let the browser predict a structural alphabet from a typed sequence — but no ONNX ProstT5 conversion was found in this research, so this is an idea, not an available path.

### Gaps
- **No speed measurements at all** for ESM-2 in a browser — no tokens/sec, no time-to-first-embedding, no memory figures, on either WebGPU or WASM. I found no source combining ESM-2 and WebGPU directly; the compatibility claim is an inference from two separate facts.
- **No ONNX conversions found for ESM-2 8M or 35M**, ESM C, ProtT5, ProstT5 or SaProt. Only 150M and 650M ESM-2 were confirmed.
- **ONNX file sizes** for the available conversions were not retrieved (the model cards did not show them in results).
- No information on whether ONNX Runtime Web (as opposed to Transformers.js) has been used for PLMs.

## Text-to-protein retrieval and protein-language models

### Takeaway
ProTrek makes natural-language protein search genuinely practical — it is published in Nature
Biotechnology, has open 35M and 650M checkpoints, and its public server already holds precomputed
embeddings for over 5 billion proteins, reportedly beating Foldseek and MMseqs2 on both speed and
accuracy for finding functionally related proteins. This is the most directly reusable item in the
whole landscape for the app's search box.

### Cited Findings
- **ProTrek is tri-modal (sequence ↔ structure ↔ natural-language function), contrastively aligned**, pairing a pre-trained ESM sequence encoder with a BERT-style text encoder. Nature Biotechnology 2025; bioRxiv preprint 2024 — [ProTrek preprint](https://www.biorxiv.org/content/10.1101/2024.05.30.596740.full.pdf); [ProTrek publication page](https://zhoubay.github.io/publication/ProTrek)
- **Reported to outperform Foldseek and MMseqs2 in speed and accuracy** for finding functionally related proteins — [ProTrek publication page](https://zhoubay.github.io/publication/ProTrek)
- **The public ProTrek server holds precomputed embeddings for over 5 billion proteins** — [ProTrek publication page](https://zhoubay.github.io/publication/ProTrek)
- **Open checkpoints at two sizes:** `westlake-repl/ProTrek_35M_UniRef50` and a 650M UniRef50 variant; code at westlake-repl/ProTrek. A separately uploaded text-encoder-only checkpoint also exists — [ProTrek_35M_UniRef50](https://huggingface.co/westlake-repl/ProTrek_35M_UniRef50); [ProTrek 650M text encoder](https://huggingface.co/yosshstd/ProTrek_650M_UniRef50_text_encoder/blob/main/README.md)
- **Evolla — natural-language Q&A about proteins.** Described as an 80-billion-parameter protein-language generative model, with architectures spanning 10B to 80B. Checkpoints such as `westlake-repl/Evolla-10B-DPO-hf` load through Hugging Face Transformers; code at westlake-repl/Evolla; public demo at chat-protein.com — [Evolla Transformers docs](https://huggingface.co/docs/transformers/model_doc/evolla.md); [Evolla preprint](https://www.biorxiv.org/content/10.1101/2025.01.05.630192.full.pdf)
- **Pinal is text-to-protein *design*, not dialogue or retrieval** — "translates human design intent into novel protein sequences" via a two-stage process (language → structure → sequence). Repo `westlake-repl/Pinal`, with usage documented in the GitHub README; HF notes it is not available via any supported Inference Provider — [Pinal model card](https://huggingface.co/westlake-repl/Pinal)
- **ProteinCLIP** has a public training dataset and 128-dim Swiss-Prot embeddings on Zenodo/HF — a very light-weight route to a text-aligned protein vector — [ProteinCLIP dataset](https://zenodo.org/doi/10.5281/zenodo.11176862); [ProteinCLIP Zenodo record](https://zenodo.org/records/11506091)
- **2026 successors (listings only, not fetched):** "ProtRLSearch: A Multi-Round Multimodal Protein Search Agent with Large Language Models Trained via Reinforcement Learning" — [arXiv 2603.01464](https://arxiv.org/pdf/2603.01464); OneProt, a multi-modal protein foundation model — [arXiv 2411.04863](https://arxiv.org/pdf/2411.04863)

### Inferences
- **"Proteins that pump ions across membranes" is a solved query shape, and ProTrek 35M is the cheap way to ship it.** The architecture is a dual-encoder: embed the user's text once with the text encoder, then do a dot product against precomputed protein embeddings. For 20k human proteins that is a 20k-row matrix multiply — milliseconds, no GPU, and small enough to run client-side. Only the text encoder needs to run at query time, and at 35M that is browser-feasible.
- **This is the natural replacement for the current entity-resolution system.** The MEMORY.md notes record painful whole-term-matching and stopword hacks (`MIN_SEARCH_SCORE = 0.34`) precisely because substring matching resolved "describe" → gene DES. A contrastive text→protein embedding sidesteps that entire class of bug: semantic queries stop being string matches. This is a strong "engineering depth" story for the 2.0 rewrite.
- **ProtRLSearch (March 2026) suggests the field has moved to agentic multi-round protein search** — which maps almost exactly onto this app's existing "LLM guide that drives the UI through typed commands." Worth fetching the paper before designing 2.0's guide, as it may provide a citable architecture for the feature the app already has.
- **Evolla at 10B–80B is not self-hostable on a hobby budget**, but it is a useful comparator and its public demo is a precedent for the UX. Realistically, a bring-your-own-API-key general LLM grounded on retrieved ProTrek hits will be cheaper and better than self-hosting a protein-specific chat model.

### Gaps
- **Licences for ProTrek, Evolla and Pinal weights were not confirmed** from primary licence files in this research. This matters most for ProTrek, which is the recommended dependency.
- **No documentation of the ProTrek server's API or query interface** was found — only that a server with 5B precomputed embeddings exists. Whether it is publicly callable, and under what limits, is unknown.
- **No independent replication** of the claim that ProTrek beats Foldseek/MMseqs2; it comes from the publication's own summary.
- ProTrek's embedding dimensionality and the size of a downloadable human-proteome embedding set were not found.
- ProtST was not covered by any search result in this research.

## Mechanistic interpretability of protein models

### Takeaway
This is where the 2026 landscape changed most in this project's favour. Alongside the academic
InterPLM/InterProt line, **Biohub shipped official sparse autoencoders for ESMC-6B under MIT —
16,384 features, every layer, TopK k=64, loadable through Hugging Face Transformers, with
agent-generated feature descriptions available for the layer-60 model.** A per-residue "what the
model sees" overlay on a 3D structure is no longer a research project; it is an integration task.

### Cited Findings
- **NEW 2026 — `biohub/ESMC-6B-sae-k64-codebook16384`: official SAEs on ESMC-6B.** Features are described as "approximately monosemantic," each ideally capturing one interpretable concept "such as a zinc-binding site or a transmembrane helix." **Codebook = 16,384 features; TopK with k = 64** (only 64 features active per position). SAEs were trained on **hidden states at every layer** of ESMC-6B; the example code loads layer 30 and layer 60, and **layer 60 is "the most heavily studied in the paper."** Output is a **sparse COO tensor of shape (batch, sequence length, codebook size)** — [biohub/ESMC-6B-sae-k64-codebook16384](https://huggingface.co/biohub/ESMC-6B-sae-k64-codebook16384)
- **Integration path is standard Transformers:** `AutoModel.from_pretrained` with `allow_patterns` for the config and layer files, then `add_sae_models` to attach the SAE to ESMC-6B, then inference; the `esm` package from PyPI is also referenced — [SAE model card](https://huggingface.co/biohub/ESMC-6B-sae-k64-codebook16384)
- **Feature labels exist but are served, not bundled:** "agent-generated feature descriptions" exist for the layer-60 k=64 codebook-16384 model, accessed **through the ESM Atlas or the Biohub Platform API, not from the repo**. Normalisation statistics are likewise only available for that layer-60 model — [SAE model card](https://huggingface.co/biohub/ESMC-6B-sae-k64-codebook16384)
- **Licence:** the SAE page lists both "mit" and "other" tags with no licence text; the SDK repo's LICENSE.md is unambiguous MIT (Chan Zuckerberg Biohub, 2026) and the README states the MIT licence covers the SAEs — [SAE model card](https://huggingface.co/biohub/ESMC-6B-sae-k64-codebook16384); [biohub/esm LICENSE.md](https://raw.githubusercontent.com/biohub/esm/main/LICENSE.md); [biohub/esm README](https://raw.githubusercontent.com/biohub/esm/main/README.md)
- **Biohub frames features as biology, not just activations:** "features derived from model representations capture principles of structure and function, forming a 'compositional grammar for protein biology'." An ESMFold2 figure annotates a predicted complex with named features: **a pore-loop selectivity filter, a BTB/T1 tetramerization domain, a voltage-sensing peripheral helix, and cytosolic juxtamembrane segments** — [Biohub news](https://biohub.org/news/world-model-of-protein-biology/)
- Biohub confirms it "used sparse autoencoders on the model's internal representations to find learned concepts, from amino acid chemistry to shared functions across unrelated proteins" — [Rosetta Commons](https://rosettacommons.org/2026/06/09/biohub-releases-open-source-models-that-utilize-evolution-to-design-disease-target-binders/)
- **InterPLM (Simon & Zou, Stanford; submitted Nov 2024)** trains SAEs on ESM-2 embeddings and reports finding "significantly more known protein concepts in SAE features than ESM neurons." Features capture catalytic active sites and zinc finger domains, plus coherent concepts that do not map to existing annotations. An LLM automates feature annotation, and interpreted features "can be used to suggest missing and new protein annotations"; features also steer model outputs. **Interactive platform at interPLM.ai; code at ElanaPearl/interPLM** — [arXiv 2412.12101](https://arxiv.org/abs/2412.12101); [InterPLM preprint](https://www.biorxiv.org/content/10.1101/2024.11.14.623630.full.pdf)
- A PNAS-indexed article titled "Sparse autoencoders uncover biologically interpretable features in protein language model representations" indicates the SAE-on-PLM line has reached a top journal — [Nature Index entry for PNAS 2506316122](https://www.nature.com/nature-index/article/10.1073/pnas.2506316122)
- **InterProt (Adams et al.) is the hosted latent visualiser for SAEs on ESM-2.** Repo `etowahadams/interprot` with a `viz` frontend plus a Python package for training/interpretation; **visualiser hosted at interprot.com, SAE weights on Hugging Face.** Architecture: **a React app calling RunPod serverless functions serving the SAEs**, runnable locally with pnpm. The paper describes it as visualising "latent activations on protein sequences and structures." PMLR v267 (2025) + bioRxiv; authors "release their code, model weights, and feature visualizer" — [interprot project record](https://awesome.ecosyste.ms/projects/github.com%2Fetowahadams%2Finterprot); [Adams et al., PMLR v267](https://proceedings.mlr.press/v267/adams25a.html); [bioRxiv 2025.02.06.636901](https://sciety.org/articles/activity/10.1101/2025.02.06.636901)
- **Related: SAEs on a structure predictor, with a visualiser.** "Towards Interpretable Protein Structure Prediction with Sparse Autoencoders" trains a Matryoshka SAE on ESM-2 in the structure-prediction setting and also releases a visualiser — [arXiv 2503.08764](https://arxiv.org/html/2503.08764v1)
- **Steering is an established capability:** "Interpreting and Steering Protein Language Models through Sparse Autoencoders" — [arXiv 2502.09135](https://arxiv.org/html/2502.09135v1)
- **Evo 2 (genomic) interpretability — Goodfire × Arc Institute.** BatchTopK SAEs were trained on **layer 26 of Evo 2** ("Evo 2 7B has 32 layers, so layer 26 is relatively late compared to our natural language model SAEs"). Features correspond to "sophisticated biological concepts" including **secondary structure, RNA molecules involved in protein synthesis, and viral-derived sequences like prophage**. Arc hosts a public visualiser and describes Goodfire as having "developed a specialized interpreter model—a sparse autoencoder—that reveals how Evo models process information internally" — [Goodfire: Interpreting Evo 2](https://goodfire.ai/blog/interpreting-evo-2); [Arc Evo mech-interp visualiser](https://arcinstitute.org/tools/evo/evo-mech-interp)
- **Goodfire follow-up (2025): the phylogeny manifold** — probes on **layer 24** activations had the highest performance for predicting phylogenetic taxa, i.e. Evo 2 encodes the tree of life — [Goodfire: phylogeny manifold](https://www.goodfire.ai/papers/phylogeny-manifold)
- **2026 follow-up exists:** an ICML 2026 paper, "Interpreting Genomic Language Models using Sparse Autoencoders," studies SAE interpretability for genomic LMs more broadly — [ICML 2026](https://icml.cc/virtual/2026/79512)
- Zenodo artifacts accompany the Feb 2025 Evo 2 interpretability work — [Zenodo 14895891](https://zenodo.org/records/14895891)

### Inferences
- **A per-residue "what the model sees" overlay on a 3D structure is highly feasible, and is the strongest "novel feature + engineering depth" candidate in this entire research.** The data shape makes it easy: the SAE emits a sparse (batch, seq_len, 16384) tensor with only **64 active features per residue**, so per protein the payload is ~`length × 64` (feature id, activation) pairs. For a 550-residue protein that is ~35k numbers — trivially serialisable as a static JSON/binary asset per protein, and directly mappable onto the existing per-residue pLDDT colouring machinery the app already has. The app already colours CA backbone ribbons per-vertex by pLDDT; swapping in "activation of feature #1234" is the same rendering path with a different scalar.
- **The agent-generated feature descriptions are what make it a product rather than a demo.** Without labels, an overlay shows "feature 8821 is active here," which is meaningless to a user. With labels, it shows "transmembrane helix" or "zinc-binding site." Critically, those labels are *only* available for the layer-60 / k=64 / codebook-16384 model via the Atlas or Platform API — so that specific checkpoint is effectively mandated, and the labels must be fetched and cached rather than derived.
- **InterProt is a direct architectural precedent worth studying before building.** It is a React frontend calling serverless GPU functions to serve SAEs, with a sequence-and-structure activation view — i.e. almost exactly the component this app would need, already built, open-source, and by authors who explicitly released code, weights and visualiser. Reading `etowahadams/interprot`'s viz layer is likely the single highest-leverage hour of implementation research available.
- **There is a $0 architecture available: precompute, don't serve.** Rather than InterProt's RunPod-serverless model (which costs money per query), run the SAE once over the 20k human proteome offline, store only the top-k features per residue, and ship static files. Live SAE inference is then only needed for user-supplied sequences — and could be omitted in v1 entirely.
- **Two interpretability tiers should be distinguished in the plan:** ESMC-6B SAEs (official, MIT, labelled, but require 6B-model forward passes) versus ESM-2 SAEs from InterPLM/InterProt (smaller, cheaper, well-documented, academic). If 6B inference proves too expensive, the ESM-2 route gives the same *feature* at lower fidelity.
- **Evo 2 interpretability is a different axis (DNA, not protein)** and is a distraction for a protein-centric explorer, with one exception: the phylogeny-manifold result ("the model encodes the tree of life") is a visually spectacular, citable finding that would suit a "universe" visualisation if the app ever adds a genomic dimension.

### Gaps
- **No release date** is stated on the ESMC SAE model card; the May 2026 ESM release is the likely date but is not confirmed for the SAE repo specifically.
- **File sizes are not stated** for the SAE weights, and the per-layer file breakdown is unclear beyond "layer 30 and layer 60" appearing in the example.
- **The Biohub Platform API for feature descriptions is undocumented in what I read** — no endpoint, schema, auth, quota or pricing. This is the key unknown blocking the overlay feature: whether labels can be bulk-fetched for 16,384 features once (ideal) or must be queried per protein (costly).
- **Whether the ESM Atlas exposes per-residue feature browsing in its UI** could not be verified — the biohub.ai Atlas page returned only its title ("ESM: A World Model of Protein Biology") to my fetch, with no content about coverage, search, downloads, API or pricing.
- **Licence ambiguity persists** on all the HF pages (dual "mit"/"other" tags, no licence text, plus an Acceptable Use Policy).
- **No feature-label dataset download** was found for InterPLM/InterProt either, only the interactive sites.
- I did not verify whether InterPLM's PNAS publication is the same work as the arXiv preprint, or a distinct paper.

### Inferences
- **The ESM1b portal is the safest variant-score dependency for an open-source app**: confirmed downloadable, covers all 42,336 human isoforms, and is hosted on a HF Space (so no licence-encumbered bulk bucket). It pairs naturally with the app's existing per-residue structure rendering — a variant heatmap along the backbone is the same rendering path as pLDDT and SAE features.
- **AlphaMissense should be treated as CC BY-NC-SA until proven otherwise.** For a project that wants to be "open-source and useful to others," shipping NC-SA data inside the repo would be a licence trap, and SA could arguably infect derived data files. Safer patterns: link out to Ensembl/UniProt/AlphaFold DB where the scores are already integrated, or fetch on demand, rather than redistributing the bulk files.
- **The three per-residue scalar tracks now available for free — pLDDT, variant effect, and SAE feature activation — are the real 2.0 feature.** Each is a `length`-sized array per protein, each uses the identical rendering path the app already has, and together they let a user ask "where is this protein confident, where is it intolerant to mutation, and what does the model recognise here?" on one structure. That is a coherent, novel, cheap product thesis.
- **AlphaGenome is not worth integrating for a protein-centric explorer.** It is DNA/regulatory, its terms are bespoke and non-commercial, its rate limits are undisclosed, and the free API shares ~1M calls/day across all users. Its presence in the plan would add licence risk and a hard external dependency for a feature tangential to proteins.

## Protein design

### Takeaway
The design stack is unusually friendly: ProteinMPNN and LigandMPNN are MIT, RFdiffusion3 shipped
open-source in December 2025 under BSD-3-Clause, and BoltzGen's code and weights are public. The
catch for a hobby project is compute, not licensing — BoltzGen's own authors recommend designing
~50,000 binders per target, which is categorically outside a $20/month budget. A "redesign this
sequence" demo is cheap; a real "design a binder" demo is not.

### Cited Findings
- **ProteinMPNN and LigandMPNN: "code and model parameters are available under the MIT license"** — [dauparas/LigandMPNN](https://github.com/dauparas/LigandMPNN); [LigandMPNN on PyPI](https://pypi.org/project/ligandmpnn/); [IPD: Introducing LigandMPNN](https://www.ipd.uw.edu/2025/03/introducing-ligandmpnn/)
- **NVIDIA-hosted ProteinMPNN diverges again:** "available for commercial use" but "governed by the NVIDIA Community Model License," with MIT in additional information — [NVIDIA ProteinMPNN model card](https://build.nvidia.com/ipd/proteinmpnn/modelcard)
- **RFdiffusion3 was released open-source in December 2025** (one report dates the open-sourcing to 2025-12-03), with training code included; the Rosetta Commons download page lists **BSD-3-Clause** — [IPD: RFdiffusion3 now available](https://www.ipd.uw.edu/2025/12/rfdiffusion3-now-available); [Rosetta Commons downloads](https://rosettacommons.org/download/); [ifeng report](https://tech.ifeng.com/c/8xLGTugT9nF)
- **RFdiffusion3 does all-atom biomolecular interaction design** — "De novo Design of All-atom Biomolecular Interactions with RFdiffusion3," published in *Science* — [PubMed 41000976](https://pubmed.ncbi.nlm.nih.gov/41000976/)
- **NEW 2026 — RFdiffusion3 hosted on NVIDIA from 2026-03-30**, governed by the NVIDIA Community Model License — [NVIDIA RFdiffusion model card](https://build.nvidia.com/ipd/rfdiffusion/modelcard)
- **RF3 tooling:** AtomWorks and RF3 are covered by Microsoft Research, and a Rosetta Commons "foundry" repo exists — [Microsoft Research on AtomWorks and RF3](https://www.microsoft.com/en-us/research/?p=1157655); [RosettaCommons/foundry](https://github.com/RosettaCommons/foundry)
- **Earlier RFdiffusion is BSD-3-Clause** per a weights mirror, and was announced as free and open source in 2023 — [RFdiffusion licence mirror](https://huggingface.co/OneScience-Sugon/RFdiffusion/blob/main/README.md); [Baker Lab 2023 announcement](https://www.bakerlab.org/2023/03/30/rf-diffusion-now-free-and-open-source/)
- **BindCraft is MIT per secondary reporting**, "made widely available under the highly permissive Massachusetts Institute of Technology (MIT) license, which allows commercial use" — [GEN News](https://www.genengnews.com/topics/artificial-intelligence/bindcraft-ai-model-achieves-one-shot-functional-protein-design/); published in Nature Methods — [BindCraft paper](https://www.bakerlab.org/wp-content/uploads/2025/03/s41592-025-02626-1.pdf)
- **BindCraft has a PyRosetta licence trap:** "for commercial purposes, PyRosetta requires a purchased license" (see LICENSE.PyRosetta.md or email license@uw.edu) — so MIT on BindCraft itself does not make the pipeline commercially free — [NIH HPC BindCraft](https://hpc.nih.gov/apps/BindCraft.html)
- **BoltzGen (Nov 2025) — all-atom generative binder design, code and weights public.** It "reframes binder design as a pure structure prediction task" and jointly trains folding and design objectives, with one model handling both design and structure prediction; described as designing "protein and peptides of any modality to bind a wide range of biomolecular targets." Code/weights at HannesStark/boltzgen; "freely available, with easy-to-use interface to specify a binder-design problem" — [MIT Jameel Clinic: Introducing BoltzGen](https://jclinic.mit.edu/boltzgen/); [BoltzGen preprint](https://www.biorxiv.org/content/10.1101/2025.11.20.689494.full.pdf); [PMC12697729](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC12697729/)
- **BoltzGen's compute recommendation is the killer constraint: "the authors recommend designing around 50,000 binders for each target"** — [MIT Jameel Clinic BoltzGen](https://jclinic.mit.edu/boltzgen/)
- BoltzGen is wrapped by many third-party runners (Rowan, Neurosnap, Tamarind, OpenProtein.AI, nf-binder-design, NIH Biowulf, PyPI `boltzgen` 0.1.4) — a mature ecosystem, mostly paid — [Rowan](https://rowansci.substack.com/p/breaking-boltzgen-now-live-on-rowan); [Tamarind docs](https://docs.tamarind.bio/tools/boltzgen.md); [NIH Biowulf](https://hpc.nih.gov/apps/boltzgen.html); [boltzgen PyPI](https://pypi.org/project/boltzgen/0.1.4/); [OpenProtein.AI walkthrough](https://docs.openprotein.ai/walkthroughs/Nanobody_binder_design_with_BoltzGen.html); [nf-binder-design](https://australian-protein-design-initiative.github.io/nf-binder-design/workflows/boltzgen)
- **Chai-2 is not open.** Reported hit rates conflict: the preprint "Zero-shot antibody design in a 24-well plate" reports a **16%** hit rate in fully de novo antibody design (20 antibodies/nanobodies against 52 targets, ≥1 hit for 50% of targets in one round), while Chai Discovery's June 2025 press release cited "close to 20%" and a third-party summary says 20%. Access is "early access to Chai-2 to select partners," requiring platform or API access rather than open weights, which "limits independent replication." Both preprints remained unpublished as of my latest source — [Chai-2 preprint](https://sciety.org/articles/activity/10.1101/2025.07.05.663018); [Chai Discovery press release](https://www.businesswire.com/news/home/20250630307418/en/Chai-Discovery-Unveils-Chai-2-Breakthrough-Achieving-Fully-De-Novo-Antibody-Design-With-AI); [Contrary Research](https://research.contrary.com/company/chai-discovery)
- Independent commentary notes Chai-2's figures come from "a company-run benchmark across 52 targets, not an externally adjudicated challenge such as CASP or CAPRI" — [Contrary Research](https://research.contrary.com/reports/chai-discovery)
- **NEW 2026 — ESMFold2 is itself a design engine with published wet-lab hit rates.** Biohub designed binders against **EGFR, PDGFRβ, PD-L1, CTLA-4 and CD45**, reporting **36–88% hit rates for compact minibinders and 15–29% for antibody-derived formats**, with nanomolar affinity, high specificity and favourable stability; PD-L1 binders restored T-cell signalling in vitro. The computational binder search "took days rather than months or years" — [Biohub news](https://biohub.org/news/world-model-of-protein-biology/); [Rosetta Commons](https://rosettacommons.org/2026/06/09/biohub-releases-open-source-models-that-utilize-evolution-to-design-disease-target-binders/)

### Inferences
- **Two design demos are cheap and one is not.** (a) "Redesign this sequence" — ProteinMPNN/LigandMPNN inverse folding on an existing AFDB backbone is MIT, tiny (a GNN, not a diffusion model), fast, CPU-feasible for single proteins, and produces an immediately legible result (a new sequence, with recovery statistics). This is the right hobby-scale demo. (b) "Design a binder" — BoltzGen/RFdiffusion3 at the recommended 50,000 designs per target is flatly outside a $20/month budget and would also be scientifically meaningless at a 10-design scale. Offering it as a toy risks misleading users.
- **Because ESMFold2's reported binder hit rates (36–88% minibinders) are dramatically higher than Chai-2's 16–20%**, and ESMFold2 is MIT while Chai-2 is partner-only, the open option now appears to dominate the closed one on this task — though the comparison is across different target sets and formats and both sets of numbers are self-reported.
- **The honest framing for a portfolio project is "explain and visualise design," not "do design."** Showing a precomputed design trajectory, or the inverse-folding sequence-recovery statistics on a known structure, demonstrates genuine understanding at zero cost; pretending to run a binder campaign does not.
- **Watch the dependency licences, not just the headline licences.** BindCraft is the cautionary example: MIT model, commercially-licensed PyRosetta underneath. An open-source project should check the full dependency chain before advertising a design feature as freely usable.

### Gaps
- **BindCraft's own LICENSE file was not read** — the MIT claim is from secondary reporting (GEN News).
- **RFdiffusion3's GitHub LICENSE was not read** — BSD-3-Clause comes from the Rosetta Commons download page.
- **BoltzGen's licence was not confirmed.** Code and weights are described as public and freely available, but no licence name was established in this research.
- **GPU requirements and per-design runtimes** for RFdiffusion3, BoltzGen and ProteinMPNN were not obtained, so the cost of even a small design demo cannot be quantified from these sources.

- ESM-3 generation capabilities were not researched (and are in any case under the non-commercial ESM3 licence, unlike the newly-MIT ESMC/ESMFold2).

## Structure search and comparison

### Takeaway
This is the cheapest, most mature, most immediately useful category for the app: Foldseek is free
open-source software with a public server and a public API requiring no authentication, FoldMason
reached *Science* in 2026 for scaling multiple structure alignment to hundreds of thousands of
structures, and the pre-clustered resources (AFDB clusters, AFESM, TED) are downloadable. These turn
"find proteins shaped like this one" into a free feature.

### Cited Findings
- **Foldseek public API requires no authentication:** an integration guide lists the endpoint as `search.foldseek.com/api` with "no authentication required" — though this is a third-party code comment, not official documentation — [ToolUniverse foldseek_tool](https://zitniklab.hms.harvard.edu/ToolUniverse/_modules/tooluniverse/foldseek_tool.html)
- **The public server is explicitly not a production service:** a guide describes it as "a public web server API rather than a production SLA service" — [Australian structural biology protein_search guide](https://australian-structural-biology-computing.github.io/protein_search)
- **Foldseek release 9 added Foldseek-Multimer**, "fully benchmarked and integrated into this release with the `easy-multimersearch` and `multimer` workflows." I found no evidence of a Foldseek 10 — [Foldseek releases](https://www.github.com/steineggerlab/foldseek/releases)
- **NEW 2026 — FoldMason published in *Science*, 2026, v. 391, n. 6784.** It "leverages the pairwise structural aligners Foldseek and TM-align for the multiple alignment of hundreds of thousands of protein structures," is "free, open-source software," and its main workflow `foldmason easy-msa` takes PDB or mmCIF and writes a FASTA alignment — [FoldMason preprint](https://www.biorxiv.org/content/10.1101/2024.08.01.606130.full.pdf); [EBSCO journal record](https://www.ebsco.com/articles/health-and-medicine/f3e2a408-0e53-59e4-91e0-03a0dc62a660/multiple-protein-structure-alignment-at-scale-with-foldmason); [FoldMason data on Zenodo](https://zenodo.org/records/17311030); [PMC11903335](https://pmc.ncbi.nlm.nih.gov/articles/PMC11903335)
- **AFDB structural clusters: 2.27M non-singleton structural clusters**, with cluster-membership files including `1-AFDBClusters-entryId_repId_taxId.tsv.gz`; browsable interactively at cluster.foldseek.com — [AlphaFold Clusters](https://cluster.foldseek.com); [AFDB cluster downloads](https://afdb-cluster.steineggerlab.workers.dev/)
- **AFESM: AlphaFold DB + ESMAtlas combined into an 820-million-entry dataset, clustered into 72.6M AFESM structural clusters, of which 5.12M are non-singleton.** Data and an interactive webserver at afesm.foldseek.com — [AFESM preprint](https://www.biorxiv.org/content/10.1101/2025.04.23.650224.full.pdf)
- **TED (The Encyclopedia of Domains): 365 million domains** for AlphaFold DB v4 — ~324M in TED100 plus ~40M in TED-redundant; the per-chain segmentation file is named for 214M chains. An older Zenodo version is marked "Dataset Restricted," so access varies by version — [TED Zenodo v5](https://zenodo.org/record/13908086); [TED preprint](https://www.biorxiv.org/content/10.1101/2024.03.18.585509.full.pdf)
- **A TED-based fold-classification benchmark exists (TEDBench)** — useful if the app ever wants a fold-level taxonomy — [TEDBench on PyPI](https://pypi.org/project/TEDBench/)
- **AFDB programmatic access:** the EBI AlphaFold API lets you "download atomic coordinates, confidence metrics, and obtain metadata"; note there have been **breaking changes to the AFDB predictions API** — [EBI AFDB programmatic access](https://www.ebi.ac.uk/training/online/courses/navigating-alphafold-database/what-is-the-afdb/accessing-searching-afdb/programmatic-access-api/); [EBI: breaking changes to the AFDB predictions API](https://www.ebi.ac.uk/pdbe/news/breaking-changes-afdb-predictions-api)
- **ProTrek claims to beat Foldseek on finding functionally related proteins** (see text-retrieval section) — a relevant counterpoint for feature design — [ProTrek publication page](https://zhoubay.github.io/publication/ProTrek)

### Inferences
- **Foldseek is the right engine for the app's "similar structures" feature, and it should run locally, not against the public server.** Foldseek is open-source C++ designed for exactly this scale; 20k human structures is a small database by its standards. Precomputing an all-vs-all human-proteome similarity matrix offline and shipping the resulting neighbour lists as static data costs $0 at runtime, avoids hammering a non-SLA public server, and gives instant responses. The public API is then only needed for user-uploaded structures.
- **This also fixes the project's current "positioned by similarity" story properly.** Today's UMAP comes from embeddings; a Foldseek-derived structural distance matrix (or a 3Di-based one) gives a second, independent, structure-grounded layout — and letting the user toggle between "sequence-model space" and "structure space" is a genuinely novel, free interaction that would make the "protein universe" more than decorative.
- **AFDB clusters (2.27M non-singleton) are the natural scaffold for scaling beyond 20k proteins.** Rather than loading millions of individual proteins, render cluster representatives and expand on demand — a level-of-detail strategy that maps directly onto the LOD trace machinery the app already has in `structure_asset_builder.py`.
- **TED domains are the key to a better unit of exploration.** Whole-protein similarity is a blunt instrument because multi-domain proteins are chimeras; TED gives 365M pre-segmented domains, so the app could let users explore *domains* and discover that two unrelated proteins share one. That is a more scientifically honest and more interesting interaction than whole-protein neighbours.
- **AFESM matters only if the app expands past known proteomes**, where its 72.6M clusters over 820M entries would be the index of choice. At human-proteome scale it is overkill.

### Gaps
- **No published rate limits** for the Foldseek public server/API, and the "no authentication required" claim is from third-party code, not official docs. Official usage policy needs checking in the Foldseek GitHub docs.
- **No file sizes or total download volumes** for AFDB clusters, AFESM or TED. The Zenodo records and AFESM site would have these.
- **No confirmed size for the AlphaFold DB human proteome bulk download** — a central number for planning this project, and unresolved here.
- **TM-align / US-align**: not covered by any search result in this research beyond FoldMason's use of TM-align internally.
- The nature of the **AFDB predictions API breaking changes** was not read — relevant if the app calls AFDB directly.
- Whether Foldseek has released a version 10 is unresolved (the releases page may not be current).

## Concrete cost estimates for applying the most promising items to 20,000 human proteins

### Takeaway
For the four most promising items, the realistic costs are: **ProtT5 embeddings = $0 (download, don't
compute)**, **Foldseek all-vs-all = $0 (CPU, local)**, **ESM-2-small embeddings = well under $1 of
rented GPU**, and **ESMC-6B SAE features = the only line item with real cost**, plausibly in the
single-digit to low-tens of dollars of rented GPU for a one-off pass. All of these are one-time
offline batch jobs whose outputs become static files, so the app's *recurring* cost stays at $0.

### Cited Findings
Facts that anchor the estimates below:
- **UniProt already publishes ProtT5 per-protein embeddings for the Homo sapiens reference proteome (UP000005640_9606) as an HDF5 file** — no inference needed — [UniProt embeddings README](https://ddbj.nig.ac.jp/public/mirror_database/uniprot/knowledgebase/embeddings/README)
- **ProtT5 embeddings are 1024-dim; ESM-2 is 320-dim at 8M, 480 at 35M, 640 at 150M** — [PMC11358375](https://pmc.ncbi.nlm.nih.gov/articles/PMC11358375)
- **ESM1b precomputed variant effects already exist for all 42,336 human protein isoforms** — no inference needed — [PMC10802723](https://pmc.ncbi.nlm.nih.gov/articles/PMC10802723/)
- **AlphaMissense precomputed scores are already downloadable** (licence caveat aside) — no inference needed — [Zenodo](https://zenodo.org/records/10813168)
- **The ESMC-6B SAE emits only 64 active features per residue** (TopK k=64) out of a 16,384 codebook, as a sparse COO tensor — [SAE model card](https://huggingface.co/biohub/ESMC-6B-sae-k64-codebook16384)
- **ESMC-6B is 6B parameters, 80 layers, distributed as F32 Safetensors, and requires a GPU**; bfloat16 is needed for flash attention — [biohub/ESMC-6B](https://huggingface.co/biohub/ESMC-6B)
- **Foldseek and FoldMason are free, open-source software**, and FoldMason is documented as aligning "hundreds of thousands of protein structures" — [FoldMason preprint](https://www.biorxiv.org/content/10.1101/2024.08.01.606130.full.pdf); [Foldseek releases](https://www.github.com/steineggerlab/foldseek/releases)
- **SimpleFold-100M "recovers ~90% of the best model's performance while being very efficient in inference even on consumer-level devices"** with an MLX backend — i.e. zero cloud cost on the developer's own Mac — [arXiv 2509.18480v4](https://arxiv.org/pdf/2509.18480v4)
- **Biohub's own binder search "took days rather than months or years"** — the only runtime datapoint I have for ESMFold2-class workloads, and it is for design, not embedding — [Biohub news](https://biohub.org/news/world-model-of-protein-biology/)

### Inferences
**These are my own order-of-magnitude estimates, not cited figures.** Stated assumptions: ~20,000
human proteins; mean length ~550 residues (so ~11M residues total); commodity rented GPU rates of
roughly $0.30–1.00/hour for a 16–24 GB card and roughly $1.50–3.00/hour for an 80 GB card; one-off
batch jobs, outputs stored as static files.

1. **ProtT5 per-protein embeddings (similarity map / UMAP layout) — $0 and ~minutes.**
   Download UniProt's human per-protein HDF5. No GPU, no inference. The resulting matrix is ~20,000 × 1024 × 4 B ≈ **82 MB float32, ~41 MB float16**, small enough to serve statically and search in-browser. *This is the highest value-per-dollar item in the entire research.*

2. **Foldseek all-vs-all structural neighbours over the human proteome — $0 and ~hours on a laptop CPU.**
   Foldseek is designed for databases orders of magnitude larger than 20k; 20k-vs-20k is a small job. Output is a neighbour list (say top 50 per protein ≈ 1M rows), a few tens of MB. Marginal cost is the one-time AFDB human-proteome download (size unconfirmed — see gaps). Risk: none; everything is local and open-source.

3. **ESM-2-small (8M–150M) embeddings, if a second embedding space is wanted — well under $1.**
   ~11M residues through a 320–640-dim model is a small workload; on a single 16 GB GPU this is plausibly **tens of minutes to ~2 hours**, i.e. **under $2 at the stated rental rates, and $0 if run on the developer's own machine**. Could also be done incrementally in free Colab sessions. The 650M/ESM-C-600M tier is perhaps 4–10× that — still trivial in dollar terms.

4. **ESMC-6B + SAE per-residue features (the flagship interpretability overlay) — the one real cost, estimated at roughly $5–50 one-off.**
   This requires a forward pass of a 6B-parameter model over ~11M residues *with* SAE hooks attached. A 6B model in bf16 is ~12 GB of weights, so it needs a 24 GB card at minimum and comfortably fits an 80 GB card; F32 distribution means a dtype cast is needed. Estimating ~1–10 hours of 80 GB-class GPU time at $1.50–3.00/hour gives roughly **$2–30**, and I'd budget **$50** for retries and the inevitable first-attempt failures. **Storage is reassuringly small**: at k=64 active features per residue, storing (feature_id uint16, activation float16) per active feature is 4 bytes × 64 × 11M residues ≈ **2.8 GB raw**, and far less if only the top ~8–16 features per residue are kept — likely **~350–700 MB**, which is shippable as static per-protein files.
   The cheaper fallback that delivers the same *feature* at lower fidelity: run **InterPLM/InterProt ESM-2 SAEs** instead, which are a fraction of the compute and come with a published open-source visualiser.

**Strategic conclusion for the 2.0 plan:** three of the four flagship capabilities — proteome-scale
similarity layout, structural neighbour search, and variant-effect tracks — are achievable at
**literally $0** because the expensive computation has already been done and published by UniProt,
EBI/AFDB, Foldseek and the ESM1b authors. The only capability that genuinely requires buying GPU time
is the per-residue SAE interpretability overlay, and that is a **one-time cost in the tens of dollars**,
not a recurring one. A 2.0 architecture of "offline batch jobs → static assets → in-browser compute,
with bring-your-own-key LLM" keeps the **recurring** bill at or near $0 while delivering the novel
feature, which is exactly the stated constraint.

### Gaps
- **No measured throughput figures** (sequences/sec or residues/sec) for ESMC-6B, ESM-2, ProtT5 or SAE-hooked inference on any specific GPU were found in this research. Every runtime number above is an informed guess, not a benchmark, and should be validated with a 100-protein pilot run before committing.
- **No GPU rental prices were sourced.** The $/hour figures are my stated assumptions, not cited facts — they need checking against current provider pricing.
- **VRAM requirements for ESMC-6B inference are not documented** on its model card beyond "GPU"; whether 24 GB suffices at typical protein lengths is unverified.
